# NextStep 제품·비즈니스 전략

> 최종 수정: 2026-09-22. 이 문서는 기능 결정의 기준입니다. 기능 요청이 오면 "어느 역할의 어느 핵심 지표를 올리는가"로 판단합니다.

## 1. 한 줄 정의

**아이 한 명을 둘러싼 어른들(부모, 선생님, 과외, 튜터)이 같은 데이터를 보고 각자 역할대로 돕게 하는 학습 운영 앱.**

기존 앱은 셋 중 하나만 합니다. 학생용 플래너·타이머(열품타, 스터디플래너류), 학부모용 알림·성적 조회(학교·학원 앱), 튜터용 수업 관리. NextStep 은 세 역할을 **한 학생 단위로 묶고** 역할별 화면을 다르게 주는 것이 차별점입니다.

## 2. 누구를 위한 앱인가 (우선순위 순)

| 순위 | 세그먼트 | 왜 먼저인가 |
|---|---|---|
| 1 | **초5~중3 자녀를 둔 학부모** | 결제자이자 설치 주도자. "내 아이가 뭘 어디까지 하는지 모르겠다"는 고통이 가장 큼. 앱을 깔게 만드는 쪽. |
| 2 | **과외·소규모 튜터 (1~15명 담당)** | 학생·학부모와 카톡으로 진도·숙제를 주고받는 비효율. 로드맵·과제·피드백을 한 곳에서 하면 "프로처럼 보이는" 가치. 유료 전환 가능성이 가장 높음. |
| 3 | **학생** | 직접 설치·결제는 적지만 리텐션의 열쇠. 학생이 안 쓰면 어른 화면은 비어 있음. 그래서 학생 화면은 "덜 귀찮게, 바로 이득"이 원칙. |

학교 담임·대형 학원은 나중입니다(계약 주기 길고 기존 시스템 있음).

## 3. 성공 가설

1. **연결 가설**: 학부모가 설치하고 자녀에게 코드를 보내면 72시간 안에 학생이 연결한다. (연결률 ≥ 50%)
2. **관찰 가설**: 학생 데이터가 쌓이면 학부모는 주 3회 이상 대시보드를 열고 격려를 보낸다. 격려를 받은 학생은 다음 주 학습 기록 일수가 늘어난다.
3. **튜터 가설**: 튜터가 로드맵을 만들면 학생 완료율이 오르고, 학부모가 그 진행을 보면서 튜터 만족도가 올라간다. 튜터는 이것을 위해 월 구독을 낸다.
4. **데이터 가설**: 3주 이상 쌓인 데이터로 만든 재능·약점 신호가 학부모에게 "돈 낼 만한 인사이트"로 인식된다.

각 가설은 아래 지표로 검증하고, 하나라도 깨지면 그 역할의 핵심 흐름을 다시 설계합니다.

## 4. 북극성 지표와 보조 지표

- **북극성: 주간 활성 가족(WAF)** — 한 주에 학생 기록 1건 이상 + 어른 1명 이상 조회가 있는 가족 수.
- 활성화: 온보딩 완료율, 학생 연결률(72h), 첫 기록까지 시간
- 참여: 학생 주간 기록 일수, 학부모 주간 조회일, 격려 발송 수, 로드맵 완료율
- 리텐션: 가족 단위 4주 리텐션
- 수익: 튜터 유료 전환율, 가족 플랜 전환율, ARPU

## 5. 수익 모델 (단계적)

| 단계 | 모델 | 대상 | 근거 |
|---|---|---|---|
| 1 (출시~3개월) | 전부 무료 | 전체 | 연결·관찰 가설 검증이 먼저. 결제 마찰 없이 데이터 확보 |
| 2 | **튜터 Pro** 월 9,900~19,900원 | 튜터·과외 | 학생 여러 명 관리, 로드맵 템플릿 저장·재사용, 학부모 공유 리포트, 수업 일정·정산 메모. 튜터는 이미 사업자라 결제 저항이 낮음 |
| 3 | **가족 플러스** 월 4,900원 | 학부모 | 재능·약점 심층 리포트, 시험 대비 자동 계획, 주간 요약 알림, 자녀 여러 명 |
| 4 | 학원 B2B (좌석당 과금) | 소규모 학원 | 튜터 Pro 가 안착한 뒤 |

원칙: **학생 화면은 절대 유료 벽을 세우지 않는다.** 학생이 막히면 전체 데이터가 멈춥니다.

## 6. 경쟁과 포지셔닝

- 학생 플래너·타이머 앱: 학생 혼자 씀. 어른이 볼 수 없거나 감시 느낌. → 우리는 "감시가 아니라 역할 분담"으로 포지셔닝. 학부모 화면의 기본 행동이 "격려"인 이유.
- 학원·학교 알림 앱: 기관이 보내는 일방향. → 우리는 가족이 주체이고 튜터가 붙는 구조.
- 튜터 관리 SaaS(웹 위주): 학생·학부모 앱이 없거나 약함. → 우리는 세 화면이 실시간으로 묶임.

메시지: **"아이 공부, 혼자 감시하지 말고 같이 돕기."**

## 7. 로드맵

### Phase 0 — 지금 (빌드 가능한 상태 만들기)
- [x] 세 역할 화면·권한, 로드맵, 학습 계획, 격려, 재능 발견, 동기화
- [ ] GitHub Actions 로 빌드·테스트 자동화 (이 커밋)
- [ ] Android Studio 첫 빌드 오류 수정
- [ ] Firebase 프로젝트 연결, 보안 규칙 강화(가족 문서에 구성원 UID 저장)

### Phase 1 — 비공개 베타 (가족 10~20팀, 튜터 3~5명)
- 푸시 알림: 격려 도착, 과제 배정, 로드맵 목표일 D-1, 학부모 주간 요약
- 멘토 다중 학생 전환 (한 기기에서 여러 학생 오가기)
- 온보딩 개선: 학부모가 설치 → 자녀에게 초대 링크 공유(딥링크) → 학생 설치 시 자동 연결
- 지표 수집(Firebase Analytics) + 위 가설별 대시보드
- 학생 화면 마찰 제거: 홈 위젯(타이머 시작), 잠금화면 타이머, 1탭 기록

### Phase 2 — 공개 출시 (Play 스토어)
- 튜터 Pro: 로드맵 템플릿, 학부모 공유 리포트(PDF/링크), 학생 여러 명
- 시험 대비 모드: 시험일 입력 → 범위 단원 → 자동 계획 → D-day 카운트
- 학교 시간표·학사 일정 가져오기(나이스/학교 앱 연동은 검토 후)
- 개인정보 처리방침, 만 14세 미만 법정대리인 동의 흐름

### Phase 3 — 확장
- 가족 플러스 구독, 자녀 여러 명
- iOS (Kotlin Multiplatform 으로 domain 공유 검토)
- 학원 B2B

## 8. 기술 결정

- **아키텍처**: 단일 모듈, 레이어(data/domain/ui) + ui 는 화면(feature) 단위 패키지. 팀이 3명 이상이 되거나 빌드가 5분을 넘기면 Gradle feature 모듈로 분리. FSD 는 웹 프론트엔드 규약이라 그대로 쓰지 않고, 그 핵심(기능 단위 슬라이스, 단방향 의존)만 가져온다.
- **백엔드**: Phase 1 까지 Firestore + Cloud Functions(연결 코드 검증, 알림 발송). 리포트·정산·B2B 가 들어오는 Phase 2 에 Kotlin/Ktor + PostgreSQL 서버를 `server/` 로 추가하고 동기화 구현체를 교체.
- **품질**: domain 은 순수 Kotlin 이라 단위 테스트 필수. 화면은 Compose UI 테스트를 핵심 흐름(온보딩, 연결, 타이머, 계획 생성)에만.
- **개인정보**: 미성년자 데이터. 최소 수집, 가족 단위 격리, 삭제 요청 시 가족 문서 전체 삭제 함수 제공.

## 9. 당장 하지 않을 것

- AI 채팅 튜터, 문제 풀이(콴다류와 경쟁하지 않음)
- 학교·교육청 공식 연동
- 커뮤니티·랭킹 (비교·감시 인상)
- 웹 버전 (모바일 3 화면이 검증된 뒤)

## 10. 의사결정 규칙

1. 학생의 기록 마찰을 늘리는 기능은 거절한다.
2. 학부모 기능은 "감시"보다 "격려·이해"를 기본값으로 둔다.
3. 튜터 기능은 튜터가 학부모에게 보여줄 수 있는 결과물(로드맵, 리포트)을 만드는 방향으로.
4. 세 역할 중 하나만 좋아지는 기능보다 둘 이상이 연결되는 기능을 우선한다.
